# 完成を判定する検証基準

テスト実行結果、対象環境、日時、失敗と修正、未実施の範囲を記録する。「コードを書いた」「ビルドが通った」と「画面上で成立した」を区別する。

## 教材データ

全問をvalidatorへ通す。ID重複、章参照、回答型、候補の整合性、説明不足、verification、hintの必要性を調べる。計算・コードで求められる正答を独立した式・方法でも照合する。外部事実の出典・確認日を残す。全問の学習目標対応、急な難化、意図のない重複を点検する。

警告は無視して消さず、採用理由か修正内容を記録する。unverifiedはエラーで教材から削除するのではなく、利用者に状態が見えるかを確認する。

## 採点の契約

採用した各形式について少なくとも下記を実行する。

| 形式 | 正常系 | 異常系・境界 |
|---|---|---|
| 単一選択 | 正解／誤答 | 空欄、未知ID、数値や配列の混入 |
| 複数選択 | 順不同の正解集合／不足／余分 | 重複、未知ID、空集合の規則 |
| 数値 | 0、負数、小数、許容誤差の内外 | 空欄、NaN、Infinity、bool、単位混入 |
| 選択式穴埋め | 全欄正解／一部誤答 | 未回答欄、未知slot、他slotの候補 |
| 並べ替え | 正しい順／誤順 | 要素の欠落、重複、未知ID |
| 対応付け | 正しい全対応／誤対応 | 重複使用、片側欠落、未知ID |
| 未検証 | 暫定正答あり／正答なし | 確定成績・分母へ混入しない |

アプリが別言語の採点実装を持つ場合は付属参照実装と同じケースを照合する。表示上の「正解」と保存したcorrectが一致することも確認する。

## 画面遷移

ホーム→章→問題→回答→採点→解説→次問→資料→元の問題→再挑戦を一巡する。復習・ブックマーク・進捗から対象問題へ移動する。未入力、二重クリック、戻る、再読み込み、画面回転・幅変更の状態を確認する。章と難易度を学習途中でも自由に変えられることを試す。

PC幅とスマホ幅で個別に操作し、キーボードのみで主要形式を解く。画面のスクリーンショットと操作結果を残す。全360問等をブラウザで操作することは必須ではないが、採用形式や重要な表示分岐を抜かさない。

## 模擬試験

開始前の条件表示、問題移動、未回答の見直し、手動提出、期限切れ、まとめて採点、二重提出を試す。再読み込みや一時切断で制限時間がリセットされないことを確認する。提出前に正解が画面に出ないことを確認する。未回答と不正解は区別して表示し、成績計算の方針を固定する。

## 保存・分離・同期

最低二人の学習者で別々に回答・ブックマークし、切り替えて混ざらないことを確認する。APIを他者のIDで呼んでも取得・更新できないことを確認する。ブラウザ再読み込み、サーバー再起動、バックアップの往復でデータが一致するか調べる。不正な復元データで元の記録が失われないことを確かめる。

同期は認証エラー、切断・再接続、同じイベントの再送、二端末の同時回答、同一IDで異なる内容、旧問題revision、ブックマーク解除の再送を試す。実同期先がなければモックでの検証と、外部未接続を明記する。実端末間で通していない機能を「実同期検証済み」と報告しない。

## 起動・納品

配布ZIPを空のディレクトリに展開し、READMEの手順で起動する。ファイルパスに空白を含む場所も想定する。サーバーはループバックに限定し、ポート競合を分かる形で処理する。別の環境にしかない絶対パスや開発用秘密を同梱しない。

Windowsの起動手順・ランチャーを優先する。Windows実機を使えなかった場合は「Windows向け手順あり／Windows実機未検証」と書く。Linux上の成功をWindowsの成功に読み替えない。

必須テストが失敗したまま完成としない。環境上実行できない必須検証は未検証として具体的に報告し、再現コマンドを添える。開発者側の自動検証と内容の確認を終えた範囲は正確に報告する。
